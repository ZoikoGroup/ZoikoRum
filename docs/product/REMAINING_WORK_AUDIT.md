## Behaviour changes

- Partial acceptance previously had no reachable milestone UI; a draft component called a nonexistent proposal endpoint. It now proposes an integer minor-unit release, displays the refund and requires professional agreement through the existing audited backend.
- Appeals previously had no owner/reviewer workflow in the UI. Owners can submit during the server-provided window and upload appeal evidence; independent officers review actual documents and step up before deciding.
- Duplicate and taxonomy draft components used incorrect URLs and payloads. They now use the repository APIs and expose their real state and errors.
- Proposal supporting documents are uploaded/downloaded using the existing scoped, audited storage endpoints; these are distinct from request attachments.
- Weekly hours are now persisted by the profile availability command rather than omitted from the UI.
- Retainers previously supported cancellation but no persistent pause. Pausing now stops future funding without changing signed terms or blocking funded deliverables. Acceptance remains manual; automatic funding is not offered.
- Enterprise sign-in now verifies signed OIDC/SAML assertions and browser/request binding. Unconfigured providers fail closed; no fixed account or unverified email claim can authenticate a user.
- The privacy draft contained invalid Python syntax, nonexistent tables and an unrestricted erasure query. It now imports cleanly, stays within facade boundaries and cannot pretend to fulfil erasure.
