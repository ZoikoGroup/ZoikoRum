# 1. Executive Intent (Locked)

The Professional Dashboard is the professional’s command center. It must enable professionals to manage services as structured offerings, control availability, pricing, and scope, respond to opportunities without friction, deliver work under governed engagement rules, and get paid predictably and defensibly.

This is not a freelancer profile editor. This is not a messaging inbox. This is a professional service operating system.

# 2. Non-Negotiable UX/UI Principles

| UX / UI Law | Enforcement |
|---|---|
| Jakob’s Law | Familiar dashboard patterns |
| Miller’s Law | ≤ 7 primary modules |
| Hick’s Law | ≤ 3 primary actions per state |
| Fitts’s Law | Large, obvious CTAs |
| Progressive Disclosure | Advanced controls hidden by default |
| Recognition > Recall | Badges, icons, labels everywhere |
| Serial Position Effect | Critical info top and bottom |
| Peak-End Rule | Clear completion states |
| Error Prevention | Locked states, confirmations |
| Doherty Threshold | <400ms system feedback |

# 3. Dashboard Architecture Overview

Global Header → Professional Summary (At-a-Glance) → Service Offerings → Incoming Requests & Proposals → Active Engagements → Deliverables & Milestones → Earnings & Payouts → Messages & Activity → Verification & Trust Status → Enterprise Readiness (Contextual) → Global Footer

# 4. Professional Dashboard Landing

Purpose: Answer in 3 seconds — “What do I need to act on right now?”

Summary Cards (Max 6):

- Active Engagements

- New Requests

- Pending Actions

- Upcoming Milestones

- Earnings This Month

- Verification Status

UX Law Applied: Pre-attentive Processing — numbers + icons = instant clarity.

# 5. Service Offerings Module (Core Differentiator)

Purpose: Shift professionals from ad-hoc proposals to structured services.

Service card fields:

- Service Name — clear, professional title

- Specialization — from taxonomy only

- Engagement Type — Advisory · Project · Retainer

- Pricing Model — Hourly · Fixed · Retainer

- Typical Duration — time-bound

- Availability — Now · 2 weeks · 1 month

- Status — Active · Draft · Paused

Primary actions (max 3): View/Edit · Pause · Duplicate.

UX Laws: Hick’s Law (3 actions max) · Recognition (visual cards) · Error Prevention (Paused ≠ deleted).

# 6. Service Creation & Edit Flow

Step-based wizard (5 steps):

- Service Overview

- Scope & Deliverables

- Pricing & Engagement Model

- Availability & Capacity

- Review & Publish

Each step auto-saves, shows completion state, and can be revisited.

UX Laws: Cognitive Load Theory (chunked steps) · Zeigarnik Effect (incomplete steps highlighted).

# 7. Incoming Requests & Proposals

Requests table columns: Buyer · Service · Type · Budget · Deadline · Actions.

Actions (max 3): View Request · Submit Proposal · Decline.

Declines require structured reason (non-punitive).

UX Law: Choice Architecture — default emphasis on “Respond.”

# 8. Proposal Creation (Professional View)

Proposal panel includes:

- Buyer requirements (read-only)

- Service alignment indicator

- Editable scope

- Pricing breakdown

- Timeline

- Assumptions & exclusions

Governance signals displayed: Contract required · Payment protection enabled · Dispute resolution available.

Actions: Submit Proposal · Save Draft.

# 9. Active Engagements Module

Engagement table columns: Buyer · Service · Status · Milestone · Payment · Actions.

Status types: Draft · Awaiting Buyer Action · Active · In Review · Completed · Disputed (rare, prominent).

UX Laws: Serial Position Effect (status first, actions last) · Proximity (milestones + payments grouped).

# 10. Engagement Detail View

Sections (collapsible):

- Engagement Overview

- Scope & Contract

- Milestones & Deliverables

- Files & Submissions

- Messages

- Activity Log

Contract is read-only; edits require formal change request.

# 11. Deliverables & Milestones

Visual timeline; each milestone shows description, due date, submission status, and payment trigger.

Actions: Submit Deliverable · Respond to Feedback.

UX Law: Peak-End Rule — subtle celebration on milestone completion.

# 12. Payments & Earnings

Earnings overview cards: Earnings This Month · Pending Release · Lifetime Earnings.

Breakdown table columns: Engagement · Milestone · Amount · Status · ETA.

Statuses: Held · Under Review · Released · Delayed (with reason).

UX Law: Trust Transparency — money never ambiguous.

# 13. Availability & Capacity Management

Controls: weekly availability slider · max concurrent engagements · temporary unavailability toggle.

Effects: updates search ranking; prevents over-commitment.

UX Law: Error Prevention — avoids burnout and disputes.

# 14. Messages & Activity

Unified engagement threads: all communication tied to engagement; files versioned; system actions included.

No external messaging required.

# 15. Verification & Trust Status

Trust badge panel displays: Trust Tier (A/B/C) · verification checklist · expiry alerts (credentials, insurance).

CTA: Complete verification →

UX Law: Motivation via Visibility — progress drives completion.

# 16. Enterprise Readiness (Contextual)

Visible only if eligible; includes enterprise-ready badge, insurance status, prior enterprise engagements, compliance attestations.

CTA: Apply for enterprise readiness →

# 17. Saved Buyers & Opportunities

Saved buyers, followed organizations, alert settings.

UX Law: Commitment & Consistency.

# 18. Error & Edge States

Handled states include: buyer unresponsive; engagement paused; payment delayed; jurisdiction restriction; dispute initiation.

Each includes: explanation · next step · support path. No dead ends.
